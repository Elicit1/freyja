# SIF CLI and API reference

## Connection

The terminal client requires only Python 3.10+ and its standard library. Configure:

```text
SIF_BASE_URL=http://127.0.0.1:8011
SIF_API_KEY=<sk- key created by the user in the SIF console>
```

Alternatively use a private JSON file:

```json
{"base_url":"http://127.0.0.1:8011","api_key":"<private service token>"}
```

Pass `--config /absolute/path/client.json` **before** the subcommand, or set `SIF_CONFIG` to its path. Do not commit the file. The client does not search for repository-local credentials. The previous `COMFY_IMAGE_*` client environment variables remain accepted as aliases; the old startup `IMAGE_API_KEY` is no longer accepted by the server.

The user signs in to the standalone SIF web console, creates a key by name, and configures that generated `sk-` value in their client. Only the create response contains the full key. The server stores hashes, and revocation takes effect on subsequent REST/MCP requests. Administrator passwords are not API keys.

`base_url` is the SIF service origin, without `/v1`. The service runs in the user's local WSL Docker as container `sif` and publishes only `127.0.0.1:8011`; the CLI runs on Windows or in WSL. The repository's `start.ps1` starts this independent local container. GPU execution uses the already configured ComfyUI backend.

## Commands

Skill recommendation for unspecified settings: **fast, 2K, 16:9, expansion OFF**. For t2i, use `--tier fast --mp 2.25 --aspect-ratio 16:9 --no-expand` to target **2048×1152**. These must be explicit because the underlying CLI/REST defaults differ. Preserve user-specified settings. For i2i, keep the source ratio and calculate MP for a 2048-pixel long edge when the user does not specify size; the example below assumes a 16:9 input.

```bash
python scripts/generate.py capabilities
python scripts/generate.py readiness
python scripts/generate.py t2i --tier fast --prompt "A moonlit botanical garden" --mp 2.25 --aspect-ratio 16:9 --no-expand --output garden.png
python scripts/generate.py i2i --tier fast --image source.png --prompt "Edit <Picture 1>. Change daylight to golden-hour lighting; preserve the subject and composition." --mp 2.25 --no-expand --output edited.png
python scripts/generate.py status JOB_UUID --output recovered.png
```

| Parameter | Values / default | Selection |
| --- | --- | --- |
| command | `t2i`, `i2i` | New image or edit an existing image |
| `--app` | `minimax-h3-image` | Discover other registered apps with `capabilities` |
| `--tier` | `pro`, `standard`, `fast`; raw CLI default `standard` | INT8 / W4A8 / Q4_K_M respectively; explicitly use `fast` when the user leaves the tier unspecified |
| `--prompt` | Required, 1–32000 characters, written in English | Translate non-English requests before submission; preserve exact requested lettering in its original language |
| `--mp`, `--megapixels` | 0.1–20; raw CLI default 4 | Target area; 1 MP means 1024×1024 pixels; explicitly use 2.25 for the default 2K 16:9 recommendation |
| `--aspect-ratio` | Numeric W:H between 1:3 and 3:1; t2i default `1:1`, i2i default `original` | Both modes accept custom ratios such as `5:4` and `2.39:1`. `original` uses the first reference's EXIF-oriented ratio |
| `--width`, `--height` | Both required together, 32–16384, multiples of 32, total ≤20 MP, ratio 1:3–3:1 | Exact canvas dimensions. Omit MP and aspect ratio when using these fields |
| `--image` | Repeat 1–16 local paths for i2i | Order defines `<Picture N>`. PNG, JPEG, or WebP, each at most 25 MiB and 40 source MP |
| `--reference-mode` | i2i `latent` (default) or `vision` | `latent` provides VAE and text-encoder references. `vision` uses only text-encoder references |
| `--n`, `--count` | Integer 1–10, default 1 | Separate single-image samplers in one persisted workflow, seeds increment from the base seed |
| `--output-format` | `png` (default), `jpeg`, `webp` | JPEG/WebP conversion happens locally in SIF after ComfyUI returns PNG |
| `--output-quality` | 0–100, default 95 | JPEG/WebP quality. PNG remains lossless |
| `--prompt-expansion` | Path to JSON controls file | Requires expansion enabled. See the expansion schema below |
| `--no-expand` | Recommended for every generation unless the user requests expansion | Turns off expansion and preserves input text; CLI/service defaults remain ON when omitted |
| `--seed` | 0–9007199254740991; random by default | Reproducibility within the selected model and workflow |
| `--output` | Local image filename with the selected format's extension | Defaults to `outputs/JOB_UUID.EXT`; variants append `-1`, `-2`, etc. Existing files require `--overwrite` |
| `--overwrite` | Explicit flag | Allows replacing an existing output |
| `--wait-timeout` | Seconds; default 1800 | Overall client wait deadline. Uses event-backed HTTP long polling and leaves pending GPU jobs intact |
| `--idempotency-key` | 1–128 characters; generated by CLI | Use the identical key and parameters to recover an ambiguous submission |

Dimensions are aligned to 32, so actual pixel area can differ slightly from the target. Do not pass steps, CFG, sampler, denoise, negative prompt, or arbitrary model filenames. H3 Image is configured for six steps, CFG 1, Euler/Simple, denoise 1. Tier selection is the supported model control.

With MP sizing, responses include resolved `width`, `height`, and `actual_megapixels`; the resolved canvas stays at or below 20 MP. Explicit dimensions are rendered directly. H3's official local guidance recommends roughly 4–20 MP, with roughly 16 MP generally preferred. The user's existing fast/2K recommendation remains the Skill default.

## Expansion controls

Pass the following object as REST/MCP `prompt_expansion`, or save it as the CLI's `--prompt-expansion` JSON file. Omit fields to use the shown defaults. Set `expand_prompt=true` and omit CLI `--no-expand` when using this object.

```json
{"max_length":8192,"thinking":true,"temperature":1,"top_k":20,"top_p":0.95,"min_p":0,"repetition_penalty":1,"presence_penalty":0,"seed":0,"instructions":"Preserve every numbered reference and the user's literal text."}
```

`max_length` accepts 1–32768, temperature 0.01–2, top_k 0–1000, top_p/min_p 0–1, repetition_penalty/presence_penalty 0–5, seed 0–9007199254740991. `instructions` adds up to 16000 characters of English guidance to the existing expansion template. SIF retains the template's structured JSON contract and extracts `expanded_caption`. The result's `effective_prompt` is the caption used for conditioning. Expansion token budget and the H3 encoder's effective prompt limit are separate. The official local documentation describes truncation at 4096 tokens.

## Output contract

Progress goes to stderr. A successful command prints one JSON object to stdout:

```json
{"job_id":"UUID","status":"succeeded","app":"minimax-h3-image","mode":"t2i","tier":"fast","seed":42,"effective_prompt":"...","images":[{"path":"/absolute/output.png","width":2048,"height":1152}]}
```

A nonzero exit code is a failure or incomplete job. Preserve any printed job ID. `status JOB_UUID` checks/downloads that job without new submission. Check the actual output before claiming an edit met the user's request.

## HTTP interface

Every Agent-facing interface requires an API key: all `/v1/**`, `/mcp`, `/health`, and API documentation routes require `Authorization: Bearer sk-…`, including discovery, uploads, polling, image downloads and Skill downloads. Attach the header to every request, even when following a URL returned by the service. Do not attempt an unauthenticated health or capability probe. The CLI attaches the configured key automatically. The public HTML/login shell is accessible before signing in; `/admin/**` uses an administrator session instead. This independent REST API uses asynchronous jobs; it is not the existing FREYJA gateway's OpenAI endpoint.

Both `POST /v1/t2i` and `POST /v1/i2i` must receive an English `prompt`. Translate the user's request before submission; keep exact requested image lettering in its original language and preserve `<Picture 1>` reference markers. Prompt expansion is not needed for translation and remains disabled under this Skill's recommendation.

- `GET /v1/capabilities`: discover parameter schema, apps, tiers, and limits.
- `GET /v1/readiness`: check installed nodes and model filenames; this does not certify VRAM capacity.
- `GET /v1/queue`: single-worker queue counts, active/unknown jobs, and waiting positions.
- `POST /v1/uploads`: raw image bytes, returns `{id,width,height,sha256}`.
- `POST /v1/t2i`: JSON `{app?,tier?,prompt,megapixels?,aspect_ratio?,width?,height?,expand_prompt?,prompt_expansion?,seed?,n?,output_format?,output_quality?}`.
- `POST /v1/i2i`: same fields plus `images` (1–16 ordered upload IDs/data URIs) or the legacy single `image`, and optional `reference_mode`. Upload files individually before submitting their IDs. The HTTP request body limit is roughly 33 MiB, so multiple large data URIs should use individual uploads.
- `GET /v1/jobs/JOB_UUID`: current state, backend prompt ID, result, and error.
- `GET /v1/jobs/JOB_UUID/wait?timeout_seconds=25`: event-backed JSON long poll, 1–600 seconds, same state/deadline semantics as MCP `wait_for_job`.
- `GET /v1/jobs/JOB_UUID/result?response_format=url`: result descriptors with authenticated URLs, dimensions, format, and each image's seed. `b64_json` returns inline base64 instead of URL fields. Combined source bytes for inline results are limited to 128 MiB.
- `GET /v1/jobs/JOB_UUID/images/0`: authenticated image bytes.
- `GET /v1/skill.zip`: portable `sif-image-generation.zip` Skill package without credentials.

Example body:

```json
{"app":"minimax-h3-image","tier":"fast","prompt":"A red ceramic teapot","megapixels":2.25,"aspect_ratio":"16:9","expand_prompt":false,"seed":42}
```

Generation returns HTTP 202 with a durable job ID and queue position. All REST and MCP submissions share one persisted FIFO queue and one rendering worker. For MCP, call `wait_for_job` to await completion on the server. For REST, use `/jobs/JOB_UUID/wait`. If a wait deadline expires, call again with the same job ID. Existing status endpoints retain their JSON responses. Results include authenticated image URLs. States `queued`, `preparing`, and `running` are pending. An `unknown` render blocks subsequent submissions from executing until completion is confirmed. Restarted services finish existing backend jobs before new queued jobs. An administrator can resolve an unknown task in the console after confirming the backend render ended.

Multi-reference example with an exact canvas and two requested candidates follows.

```json
{"tier":"fast","prompt":"Edit <Picture 1>. Use the coat from <Picture 2> and the room from <Picture 3>. Preserve the person's identity and pose.","images":["PERSON_UPLOAD_ID","COAT_UPLOAD_ID","ROOM_UPLOAD_ID"],"width":2048,"height":1152,"expand_prompt":false,"reference_mode":"latent","n":2,"seed":42,"output_format":"webp","output_quality":95}
```

Use `Idempotency-Key` for programmatic submissions. Reusing a key with changed parameters returns HTTP 409. Invalid profile, resolution, aspect ratio, unknown fields, or missing image returns 422; missing, invalid, or revoked API keys return 401. Resolve the cause before retrying. Do not retry render failures as an unlimited loop.
