# 故事创作与写入前自审

让故事中的人物因处境作出选择，让选择产生后果。先在当前任务中写出可审查的故事草稿，找到并修复问题，再创建或更新 FREYJA 中的剧情记录。读到本 Skill 不代表已经完成审稿，也不保证故事绝对合理。

## 开始创作前

1. 确认任务是原创、续写、改编还是重写，整理用户的创作目标、题材、篇幅、视角、结局要求及已确认设定。区分用户事实、原作事实与本次可自由创作的部分；不要把自己的提议冒充已确认事实。
2. 通过 `list_skills`、`read_skill` 读取 `freyja-platform-guide`，理解业务层级。读取本 Skill 后，用返回的 `versionId` 调用 `read_skill_file`，在设计前读取 [故事设计方法](references/story-design.md)，在审稿前读取 [故事审稿方法](references/story-review.md)。参考文件缺失或版本变化时先重新发现和读取，不能声称完成未执行的检查。
3. 已有项目用 `get_project_outline`、`get_project`、`get_episode` 和 `search_assets` 等当前可用工具读取相关大纲、前集剧本、人物及本次修改对象；工具参数以当前 MCP schema 为准。概览和简介不足以证明某件事发生过，必要时读正文。只读取授权项目；修改前取得当前指纹。
4. 原创可在用户委托内设计新事实。续写继承已落库事实；改编保留原作已确认的人物、规则和结局，未获授权不能借“修漏洞”改写核心设定。事实不足时标明未知；只有影响核心创作决策且不能从现有资料确认的信息才询问用户。

## 设计 → 草稿 → 自审 → 修稿 → 写入

### 设计与草稿

先确定故事的核心冲突和人物选择，再写事件，不从镜头、资产或视频提示词倒推剧情。按任务规模，在当前上下文中保留简短工作记录：

- **人物目标**：想得到什么、为什么现在必须行动、已知什么、有什么能力和限制、失败或成功要付什么代价。
- **事件因果**：前因 → 人物选择 → 阻力 → 结果 → 新局面。每场记录前后变化；关系、情绪或认知变化也可以推动故事。
- **信息状态**：客观事实、观众所见、各角色所知及获知途径；角色不能直接使用作者或未来剧情才知道的信息。
- **铺垫与回收**：需要时记录线索的真实含义、可见表现、当时的合理解释、计划回收点与当前状态。计划不等于已经埋设，未来回收不能冒充已写成的内容。
- **连续性事实**：与当前冲突有关的时间、位置、关系、道具和世界规则，注明依据与未知项。

短故事可用几行完成这些记录；无需固定幕结构、数量配额、强行反转或给每件道具安排伏笔。草稿要包含实际发生的事件与关键选择，不能只有“冲突升级”“埋下伏笔”这样的写作意图。

### 举证自审与修稿

切换到审稿视角，把草稿当作待验证文本。按审稿参考检查人物动机、剧情因果、推进、信息逻辑、铺垫回收、连续性和高潮结局；对相关结论引用场次、事件或短句作证，不必输出逐步思考过程。

- **阻断问题**：人物无依据知情、核心因果断裂、解决冲突依赖未建立的规则、违反已确认事实或用户锁定要求。存在时先修稿，不调用工具保存受影响的剧情正文，也不通过批量创建或 `append_storyboard` 绕过。
- **改进建议**：表达、节奏、对白或风格上的可选优化。不能把个人偏好、开放式结尾或暂未回收的合理长线伏笔当作硬伤。
- 每个问题写清“情节依据 → 问题 → 对故事的影响 → 修改”，优先修根因。修改后复查前因、角色知情时间和后续结果，不能只修改审稿结论。
- 默认初审后最多修订两轮，每轮修稿后复查；没有阻断问题就结束。两轮后仍有阻断问题时停止保存相关剧本，向用户说明具体冲突及需要的信息或取舍，不能宣布通过或无限重写。
- 判断按故事既定规则进行。奇幻、科幻允许已建立的特殊能力；不能为了现实常识擅自删除超自然设定，也不能为解围临时发明能力。

### 简短说明，再保存

没有未解决的阻断问题时，先给出简短审稿摘要，再自动继续用户已授权的创建或修改，不额外要求确认：

> 自审：发现了〔具体问题〕，已改为〔关键修正〕；复查〔相关前后情节〕后，未发现未解决的阻断问题。〔仍存在的非阻断建议或资料限制；无则省略。〕

没有发现问题时，列举一两项实际核对的因果或信息来源，不编造修改经历，不宣称“满分”“绝无漏洞”。资料不足以核对核心事实时不能靠一句免责声明放行。用户明确需要完整报告时再展示详细问题记录。

- 审核的是准备提交的同一份正文；写入前如再次改变核心情节，重审影响范围。
- 用现有项目、剧集、场次、镜头组和分镜工具按父子依赖保存；新项目的画幅选择仍遵守平台要求。项目梗概、分集 `scriptContent` 与镜头 `scriptContent` 只放对应故事内容，审稿报告和工作记录不混入剧情字段，也不擅自占用用户备注或修改已有设定。
- 通过授权且当前开放的 MCP 工具执行，保留锁定、字符串 ID 和并发指纹约束；关键写入后读回核对持久化文本是否为审过的版本。保存失败不代表可以换未经审查的剧情重试。
- 故事审稿通过后再按平台指南进入分镜、资产与视频卡片制作；本 Skill 不替代摄影、分镜和模型提示词 Skill，不自动发起媒体生成。

## 续写与局部修改

新增一集前读取相关前集及已确认的大纲；不要要求先创作完整季才允许写一集。局部重写检查它的依赖和后果，纯查询、排序、媒体更新不重新审整个故事。用户提供不可改动正文时，指出冲突而不偷偷修正；核心冲突未解就暂停受影响的剧情写入。

工作记录保留在当前任务中，本 Skill 不提供持久伏笔数据库。跨聊天时重新从已保存剧情恢复事实；无法读取的未来计划保持未知，必要时向用户取回，不能承诺记住上次没有保存的安排。
