# MiniMax H3 运镜与拆镜

把已确认的剧情、画面或关键帧转成可执行的摄影方案。先判断观众此刻要看清什么、站在谁的位置看，再决定摄影机是否移动、如何移动，以及何时切镜。本 Skill 基于 Seedance 运镜方法本地化，H3 写法与平台约束已另行适配；来源及许可见 [来源与适配边界](references/sources.md)。

## 读取与职责

- 运镜设计先读 [运镜语言](references/camera-language.md)。规划镜序、拆镜、对白覆盖和接戏时再读 [拆镜与连续性](references/shot-planning.md)。
- 把方案写成 H3 视频提示词时读 [H3 与 FREYJA 映射](references/h3-mapping.md)，同时通过 `list_skills`、`read_skill` 加载 `h3-prompt-writing`；按其返回的 `versionId` 用 `read_skill_file` 读取 `references/base-en.txt` 或 `references/ref-en.txt`。读取期间版本变化则重新发现，不能拼接两个版本的规则。
- `freyja-platform-guide` 管平台流程、资源限制及声音使用；`story-writing` 管故事设计与自审；`camera-direction` / `cinematography` 若参与任务，继续负责其原有剧情结构与导演规划。本 Skill 补足逐镜摄影和切镜决策，不重写故事，不修改其他 Skill 或系统参数。
- 只有镜头方案需求时直接给方案，不为完成本 Skill 调用生成接口。已有剧情、画幅、风格、镜头长度及锁定项优先；缺少事实时保留未知，影响方案成立的必要信息才询问。

## 先读当前材料

读取当前剧本和受影响的前后镜头、人物/造型/道具、场景、实际参考图及已接受的尾帧；在 FREYJA 使用现有读取工具，业务 ID 保持字符串。只看到文本时不能声称已核验图片、成片或摄影机运动。

用简短内部判断确定：

1. 本镜让观众新知道什么，或延续何种观察、动作、情绪？是叙事、展示还是纯观察？产品展示、环境空镜不强造冲突或反转。
2. 主体真实在做什么，起点和终点是什么？信息揭示、视线或声音是否会触发摄影机行动？不为了运镜新增走位、台词、开关门、道具或光源变化。
3. 当前空间、轴线、创作者锁定及参考图允许什么摄影路径？哪些面孔、手部、持物或空间关系最容易失真？

将判断落实为可见动作、画面关系和可听事件。不要把“权力转移”“情绪峰值”等分析词直接当生成提示词。

## 每镜的摄影方案

按任务复杂度填写，简单镜头一句话也可表达完整：

| 项目 | 应表达的内容 |
| --- | --- |
| 目的与切镜依据 | 本镜展示什么；为什么从上一镜切来，或为什么保持连续 |
| 起幅与空间 | 景别、机位高度/朝向、轴线侧、主体位置与视线，必要的焦段观感 |
| 摄影机行为 | 固定或一个主导运动；摄影机移动、原地转动、变焦、调焦分别说明 |
| 触发、幅度与节奏 | 从哪个实际动作/声音开始，移动范围，缓起、匀速、追随、制动或保持 |
| 主体关系 | 跟随、领先、侧向并行、让主体经过、揭示或观察；人物与摄影机的运动不要混为一谈 |
| 落幅与交接 | 最后看见什么；结束、续接、剪辑边界、揭示、展示停留或循环 |
| 连续性与易错点 | 人物/造型、双手、道具归属、站位、屏幕方向、灯光及声音，下一镜接什么 |

**一个主导运动是常用简化策略，不是禁止复合运动的模型限制。** 固定机位也可承载完整动作。需要复合运镜时说明分阶段触发与可达路径；不要把推近、升空、环绕、甩镜同时堆在几秒里。创作者给出互相冲突且无法同时满足的硬要求时，指出冲突，不擅自取消锁定。

## 保持连续还是拆镜

- 同一目标的准备、执行、结果优先保留完整动作链。只有距离、轻微角度或注意中心变化时，先考虑推拉、摇移或调焦；不能为了景别种类丰富而碎切。
- 新信息、观众视点、人物反应、空间关系、叙事时刻或有意义的节奏变化，可以支持切镜。每次切镜都要有本场材料中的依据；接触和受力是剧情重点时，选看得清的机位，不让运镜遮住动作。
- 时长先按完整对白与自然动作估算，并行动作共用时间。普通动作常见 3–5 秒、较长镜头可参考 7–8 秒；这些是参考而非配额。预计超过 8 秒时积极寻找完整动作边界、对白轮次或叙事节点；保留明确的连续长镜要求，核实当前工作流与算力。10 秒及以上的当前部署风险及帧数对齐按 guide 处理，不谎称 H3 只能生成短镜头。
- 拆镜后完整保留剧情与原台词，核对上一镜末态和下一镜起态。不把交接拆成凭空换手，不让同一动作在两个镜头重新开始；不靠加速、慢动作、删词或空等凑时长。
- 平台 `DramaShotGroup` 是连续镜头容器，`DramaShot` 是独立业务分镜；单次 H3 提示词里的 `[Shot N]` 是该次视频内部的镜头。默认每个业务分镜写一个连续 `[Shot 1]`，不能为完成镜头组把整组切镜塞进单个请求。

## 交付与验收

给出范围内的镜头方案、每镜时长、起止状态、简短运镜/切镜理由和必要限制。已授权填写 FREYJA 时，用现有合法字段与下拉值，保留 `AUTO` 与创作者锁；摄影方案不是新的 API 字段，不虚构 `cameraPath`、逐帧轨迹或自动跨镜混音能力。写入后读回，确认模式、时长、提示词和素材顺序一致。

提交前按真实材料检查：运镜是否有目的，路径是否可达，推轨与变焦是否混淆，动作/台词是否完整，首尾帧是否相容，前后镜方向与持物是否接上，H3 段落与媒体编号是否正确。生成后另行验收实际运动、构图、遮挡、身份漂移和声音；保存了提示词不等于已验证成片。
