# 视频作为生成参考

在 `REFERENCE_MODE` 中，参考视频与参考图、独立参考音频并列。普通镜头输入列表名为 `refVideos`，接续片段为 `draft.segments[].referenceVideos`。数量、每段/总时长、帧数和像素预算，以所选模型及服务端有效限制为准，不把上传源文件的长度上限当作模型可直接参考的长度。支持保存草稿；实际生成需要先完成服务端片段预检，并使用已通过在线验收的模型。节点离线、能力未验证和片段非法是不同原因，不能声称已完成生图或生视频。

## 什么时候需要提取特征

这里的“提取特征”指可选的 **ControlNet 控制信号预处理与应用**。普通视频参考本身也会经过模型的视频编码，但不需要额外打开 ControlNet。先明确创作者希望沿用的是风格、节奏，还是具体身体姿态、空间结构与轮廓运动，再选择是否提取；不因为上传了视频、视频不是 24fps，或开启了接续，就默认提取。

| 创作目标 | 建议与控制类型 | 保留范围与限制 |
| --- | --- | --- |
| 大致参考舞蹈风格、动作语义、表演节奏、氛围或运镜意图，允许模型重新编排 | 普通视频参考，ControlNet 关闭 | 在参考说明和提示词中表达沿用/替换关系；普通参考也可能带入源外观，须验收 |
| 尽量跟随源人物的舞步、肢体姿态与动作时序，同时替换身份或服装 | 优先查询 `POSE` 骨架控制是否可用 | 使用清楚、少遮挡且身体尺度适合目标构图的源视频；骨架不保证细指、表情、服装或精确接触完全一致 |
| 希望保持空间纵深、人物/物体前后关系及较强的体积结构 | `DEPTH` 深度控制 | 深度不是人体关节控制，也不直接控制身份；场景几何和源运镜仍可能一同影响结果 |
| 希望保留人物外轮廓、物体边缘与轮廓随时间的变化 | `CANNY` 硬边缘或 `HED` 柔和边缘 | 会携带更多源服装/背景轮廓，不等价于只迁移舞步的骨架；按想保留的结构选择 |
| 建筑直线、室内硬装边界等直线结构更关键 | `MLSD` 线段控制 | 不作为舞蹈关节跟随的替代 |
| 希望使用稀疏线稿的大致轮廓 | `SCRIBBLE` 涂鸦控制 | 保留较粗结构，不能宣称等同精确动作捕捉 |
| 希望保留明暗结构与运动，减少颜色作为控制信号的影响 | `GRAY` 灰度控制 | 控制副本去色，普通语义视频仍可能保留原彩色信息；不是去身份或纯动作提取 |
| 已制作白底彩色目标框及轨迹，要按布局控制对象位置 | `LAYOUT` | 必须有已准备的布局视频；不会从普通实拍视频自动检测、跟踪并生成框 |
| 已有与所选控制模型匹配的骨架/深度/边缘等控制视频 | `PREPARED` | 跳过预处理；须确认已处理素材的类型、格式与实际兼容性，不能把任意原视频标成已提取 |

例如“参考这段舞蹈的感觉，动作自由发挥”通常先用普通语义参考；“换成我的角色，尽量按源舞步和时序跳”应优先评估 Pose，并用目标人物图约束身份；“保持同一画面轮廓与动作轨迹”可评估边缘控制。不能仅凭“舞蹈”“动作迁移”等字词断言必须使用某类型，按用户真实的保留目标决定。需求不明确且不同选择会明显改变画面时，简短澄清要保留什么；已有明确要求直接执行。

ControlNet 是结构约束，不保证逐帧复刻、确定性换脸或任意运镜迁移。避免同时要求完全不同的目标姿态和强约束源姿态；多个信号冲突时先协调素材和意图，不无限提高强度。`controlStrength`/普通模式的 `strength` 是 ControlNet 强度，不是通用视频参考强度；取值服从接口，首次可用默认 1，后续依据实际成片调整。

## 查询当前支持与配置位置

调用 `get_shot_continuation_options`，传真实 `dramaId/shotId` 及配套 `providerId/modelCode`，读取实际 `controlTypes`、节点健康、`h3` 与 `referenceVideo` 的验收状态。仅不带模型返回的完整枚举，不能证明某预处理器当前可用。Pose 需要 DWPose，Depth/HED/MLSD/Scribble 需要相应预处理器及权重；部署缺失时报告具体类型不可用。不要默默改用 Canny，或把安装节点说成已完成 GPU 效果验收。

- **普通镜头**：通过 `update_shot` 等工具保存 `refVideos`；读取完整接续草稿，在保持 `draft.enabled=false` 的情况下用 `save_shot_continuation` 保存 `draft.controlNet`，字段为 `enabled/referenceId/controlType/strength`。`referenceId` 必须匹配已保存参考视频的一项 `id`。
- **接续镜头**：在目标 `draft.segments[]` 中保存 `referenceVideos` 与 `controlNetEnabled/controlVideoId/controlType/controlStrength`。`controlVideoId` 必须是本段挂载视频的 `id`，不能用资源托盘或另一段的 ID；按 [接续模式流程](continuation-mode.md) 准备和提交。
- 多视频时显式选择唯一控制源，其他视频可继续作语义参考；没有参考视频不能启用 ControlNet。特征在渲染时由后台预处理并应用，目前没有独立的 MCP“提取并导出控制视频”工具，不虚构 `extract_features` 等接口或已提取的文件地址。
- 仅打开接续不需要 ControlNet；段间实际尾部由系统 Guide 接续，不能误用源视频 Pose 代替上一段生成上下文。`contextWindows` 是片段内部独立能力，默认关闭；与 ControlNet 联用须有 `contextWindowsWithControlNet=true` 的组合验收。

## 明确来源和片段

- 已上传并归档的视频：`sourceType=DIRECT_URL`，提供 `sourceVideoUrl`，省略分镜及 Take ID。
- 分镜当前视频：`sourceType=SHOT_CURRENT`，只提供 `sourceShotId`，预检时固定当前视频版本。
- 历史版本：`sourceType=SHOT_VIDEO_TAKE`，提供 `sourceShotId` 与 `sourceVideoTakeId`，不能附带客户端猜测的 URL。
- 所有业务 ID 都保留原字符串。每项提供稳定 `id`，列表按顺序对应 `<Video 1>`、`<Video 2>` 等。
- `startSeconds/endSeconds` 指源视频的秒级范围。未提供终点时表示源片结尾；这不改变目标镜头时长。视频过长时明确选择片段，不能默默截掉其余内容。
- `includeAudio` 默认关闭，仅在创作者明确需要、素材含音轨且模型允许时开启。原音是生成条件，不会直接混入产物；音乐仍服从创作者明确要求。

## 写参考意图

`referenceDescription` 明确希望参考的内容，以及视频与其他素材的关系。例如：“参考 Video 1 的起身节奏和镜头推进，人物外观采用 Picture 1；不使用视频原音。”

提示词 AI 未收到视频像素时，只能根据创作者说明编写，不能依据文件名编造动作或运镜。缺少说明时保留未指定状态，并引导创作者补充。不能承诺逐帧复刻、确定性换人或不存在的参考强度参数。

H3 参考模式继续使用六段结构，按实际清单引用各个 `<Video N>`、`<Picture N>`、`<Audio N>`，在主体定义、保留分析和动态描述中说明关系。素材、裁剪范围、顺序或音轨选项变化后，检查或重新生成提示词。原音关闭时，不能把源片声音写成已提供条件。

人物外观来自目标角色图、动作来自视频时明确写出两者分工，避免提示词又要求复制源人物身份。接续模式素材编号仅对本段有效；原音参与时，Audio 编号先按启用原音的视频顺序，再接独立参考音频，不能只按 `refAudios` 从 1 开始编号。

## 帧率和动作时间

当前 H3 参考准备默认统一为固定 24fps，Java 调用 FFmpeg 按时间戳抽帧或补帧，随后 FFprobe 校验真实输出；源文件保留，使用处理后副本。不是把源视频声明成 24fps 后强行按帧播放，因此不应改变动作速度，也不需要用户先手动把 25/30/60fps 视频改好再上传。具体解码帧率仍以当前模型配置为准；接续自动帧裁片要求 24fps。

帧率归一化不是骨架/深度等特征提取，也不是光流补帧或慢动作。即使平均帧率显示 24fps，可变帧率也要按统一时间轴处理。动作顺序、持续时间和参考源范围保持用户意图；不能借转帧率把较短动作拉长或加速。

接续时先调用 `split_shot_reference_video` 分配绝对源帧范围，后台准备阶段在统一 24fps 时间轴上再裁片；保留返回的 `sourceStartFrame/sourceEndFrame` 和配套秒数，不逐段从小数秒重新建立采样相位。源片必须覆盖生成所需的真实范围和重叠，技术补齐不能掩盖源动作不足。

## 在平台提交

在多模态参考渲染工坊选择视频，查看实测元信息，保存配置并预检片段，再检查提示词与预览后提交。服务端冻结具体 Take、片段范围和媒体内容；排队后切换来源分镜当前视频，不会替换已排队任务的输入。

`FIRST_LAST_FRAME` 不接受视频参考。切换模式时保留素材草稿，生成前应主动处理不兼容输入。视频可以单独作为视觉参考；仅独立音频仍按模型的唯一模态限制校验。

结果沿用分镜 Take 历史，任务和历史版本中可以查看本次参考视频来源。ComfyUI 离线时仍可编辑草稿，普通视频预检可以准备媒体；接续素材准备需先通过包含节点能力的预览。任何准备成功均不代表 GPU 生成可用或控制效果已经验收。

## 通过 MCP 提交普通参考镜头

1. 读取真实镜头、已有 `refVideos` 和当前指纹，查询所选模型的实时参考能力。先保存有序素材和最终提示词；需要 ControlNet 时按上节保存完整草稿，读回检查设置和新的 `editFingerprint`。关闭接续的普通请求最多 15 秒，并受模型更小范围和实际资源限制。
2. 调用 `prepare_shot_reference_video`，传 `dramaId/shotId/providerId/modelCode`、稳定 `requestId` 和最新 `expectedFingerprint`，取得 `preflightId`。用 `get_shot_reference_video_preparation` 轮询至 `READY`，核对实际片段元信息。
3. 生成已获授权且模型在线、参考能力已验收时，调用 `render_shot_video`，使用同一提供商与模型、有效 `size`、该 `preflightId`、最新指纹及独立稳定请求 ID；已开启接续的镜头使用 `render_shot_continuation`。
4. 用 `get_shot_continuation_render` 查询返回的真实任务 ID，此查询也支持普通镜头视频任务。检查成功状态和输出，再实际观看动作时序、姿态、手脚接触、身份、背景与声音；不能以任务提交成功声称动作已迁移。

保存、预检、渲染是不同步骤。修改视频内容、来源 Take、范围、顺序、原音、提示词或模型后重新准备；重试同一写请求沿用原请求 ID 和相同输入。`UNVERIFIED`、离线或缺预处理器时报告具体阻断，不修改验收标记绕过保护。

## 通过 MCP 上传参考视频

1. 计算本地文件真实字节数和 SHA-256。调用 `prepare_asset_video_upload`，提供授权的字符串 `dramaId`、稳定 `requestId`、不带路径的 `fileName`、`contentType`、数值 `size`、`sha256`，可选同项目 `shotId` 和 `referenceDescription`。支持 MP4/WebM/MOV/MKV；大小和时长遵循素材配置，默认 256 MiB、600 秒。
2. 用客户端已有 HTTP/文件能力向返回的 `uploadUrl` 发送 multipart POST，原样提交全部 `fields`，最后放真实 `file`。视频字节不进入 MCP 参数，不发送 Base64，不把本地路径当成已上传文件。凭证有效期15分钟。
3. 调用 `complete_asset_video_upload`，提交独立 `requestId`、授权 `dramaId` 和原 `uploadId`。服务端流式校验大小、ETag、摘要和真实视频格式，并自动登记至视频素材库。只有此步骤返回的 `url` 才是正式素材地址。
4. 将返回的 `reference` 按顺序加入分镜 `refVideos`，明确片段范围和参考说明，再通过 `update_shot` 等业务接口保存。上传不会自动覆盖分镜、生成提示词或执行渲染。每个文件独立申请和确认，可重复上传多个文件；引用数量取决于生成模型配置。
5. 超时使用原确认 `requestId` 重试；同一 `uploadId` 即使换确认请求也只登记一个视频素材。不要输出签名字段或大段调试内容。

视频编辑卡片默认折叠，展开后加载预览和片段编辑；上下移动会改变 `<Video N>` 顺序，修改后需要重新检查或生成提示词。
