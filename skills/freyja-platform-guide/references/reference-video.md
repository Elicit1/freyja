# 视频作为生成参考

在 `REFERENCE_MODE` 中，参考视频与参考图、独立参考音频并列。输入列表名为 `refVideos`，数量以所选模型 `maxVideos` 及网关模型能力配置的有效交集为准，不设置固定单段限制。支持保存草稿；实际生成需要先完成服务端片段预检，并使用已通过在线验收的模型。节点离线、能力未验证和片段非法是不同原因，不能声称已完成生图或生视频。

## 明确来源和片段

- 已上传并归档的视频：`sourceType=DIRECT_URL`，提供 `sourceVideoUrl`，省略分镜及 Take ID。
- 分镜当前视频：`sourceType=SHOT_CURRENT`，只提供 `sourceShotId`，预检时固定当前视频版本。
- 历史版本：`sourceType=SHOT_VIDEO_TAKE`，提供 `sourceShotId` 与 `sourceVideoTakeId`，不能附带客户端猜测的 URL。
- 所有业务 ID 都保留原字符串。每项提供稳定 `id`，列表按顺序对应 `<Video 1>`、`<Video 2>` 等。
- `startSeconds/endSeconds` 指源视频的秒级范围。未提供终点时表示源片结尾；这不改变目标镜头时长。视频过长时明确选择片段，不能默默截掉其余内容。
- `includeAudio` 默认关闭，仅在创作者明确需要、素材含音轨且模型允许时开启。原音是生成条件，不会直接混入产物；音乐仍服从创作者明确要求。

## 写参考意图

`referenceDescription` 明确希望参考的内容，以及视频与其他素材的关系。例如：“参考 Video 1 的起身节奏和镜头推进，人物外观采用 Picture 1；不使用视频原音。”

提示词 AI 未收到视频像素时，只能根据创作者说明编写，不能依据文件名编造动作或运镜。缺少说明时保留未指定状态，并引导创作者补充。不能承诺逐帧复刻、确定性换人或不存在的参考强度参数。

H3 参考模式继续使用六段结构，按实际清单引用各个 `<Video N>`、`<Picture N>`、`<Audio N>`，在主体定义、保留分析和动态描述中说明关系。素材、裁剪范围、顺序或音轨选项变化后，检查或重新生成提示词。原音关闭时，不能把源片声音写成已提供条件。

## 在平台提交

在多模态参考渲染工坊选择视频，查看实测元信息，保存配置并预检片段，再检查提示词与预览后提交。服务端冻结具体 Take、片段范围和媒体内容；排队后切换来源分镜当前视频，不会替换已排队任务的输入。

`FIRST_LAST_FRAME` 不接受视频参考。切换模式时保留素材草稿，生成前应主动处理不兼容输入。视频可以单独作为视觉参考；仅独立音频仍按模型的唯一模态限制校验。

结果沿用分镜 Take 历史，任务和历史版本中可以查看本次参考视频来源。ComfyUI 离线时可以保存与准备素材，生成效果仍须在线验证。

## 通过 MCP 上传参考视频

1. 计算本地文件真实字节数和 SHA-256。调用 `prepare_asset_video_upload`，提供授权的字符串 `dramaId`、稳定 `requestId`、不带路径的 `fileName`、`contentType`、数值 `size`、`sha256`，可选同项目 `shotId` 和 `referenceDescription`。支持 MP4/WebM/MOV/MKV；大小和时长遵循素材配置，默认 256 MiB、600 秒。
2. 用客户端已有 HTTP/文件能力向返回的 `uploadUrl` 发送 multipart POST，原样提交全部 `fields`，最后放真实 `file`。视频字节不进入 MCP 参数，不发送 Base64，不把本地路径当成已上传文件。凭证有效期15分钟。
3. 调用 `complete_asset_video_upload`，提交独立 `requestId`、授权 `dramaId` 和原 `uploadId`。服务端流式校验大小、ETag、摘要和真实视频格式，并自动登记至视频素材库。只有此步骤返回的 `url` 才是正式素材地址。
4. 将返回的 `reference` 按顺序加入分镜 `refVideos`，明确片段范围和参考说明，再通过 `update_shot` 等业务接口保存。上传不会自动覆盖分镜、生成提示词或执行渲染。每个文件独立申请和确认，可重复上传多个文件；引用数量取决于生成模型配置。
5. 超时使用原确认 `requestId` 重试；同一 `uploadId` 即使换确认请求也只登记一个视频素材。不要输出签名字段或大段调试内容。

视频编辑卡片默认折叠，展开后加载预览和片段编辑；上下移动会改变 `<Video N>` 顺序，修改后需要重新检查或生成提示词。
