# 业务架构与创作对象

## 叙事层级

`短剧 Drama → 剧集 DramaEpisode → 场次 DramaScene → 镜头组 DramaShotGroup → 分镜 DramaShot`

| 对象 | 用途与边界 |
| --- | --- |
| 短剧/项目 | 一部作品的总容器，保存世界观、简介、题材、全局视觉风格和画幅。 |
| 剧集 | 组织一次剧情推进与阶段性收束；继承所属作品的基础设定。不要把每个地点误建成一集。 |
| 剧情场次 | 一段具有明确叙事时空的戏，例如“第1集·夜·旧宅会客厅”。时间或地点发生叙事性改变时通常另建场次。 |
| 镜头组 | 同一场次内的连续动作链、对白轮次或连续情绪事件，记录组的叙事目的。它可含多个机位和景别，不等于一条不能剪切的长镜头。 |
| 分镜/镜头 | 可单独配置剧本、时长、人物造型、视觉输入和视频提示词的生成单元；是组内排序、渲染、候选视频选择的基本单位。 |

组是创作上推荐的连续性容器；旧数据和草稿可有未分组镜头，不捏造组 ID。需要平台的组内邻镜首尾续接时，先建立正确的组与顺序。连续镜头组的串行批渲染也不意味着所有镜头必须使用同一帧构图。

例如：“来客进门→主人抬眼认出→来客递出信封”可以放在一个镜头组，用进门全景、主人反应近景、递信中景表现同一连续事件。不要把抬手、手停下、手继续伸出机械拆成三个组。

## 叙事场次与场景资产

`DramaScene` 回答“剧情在何时何地发生”；`ResScene` 回答“这个空间长什么样”。同一“旧宅会客厅”场景资产可被多个剧集的不同场次复用，每个场次有自己的剧情与时间状态。

镜头通常继承场次绑定的环境，也可指定本镜场景资产或关键图主视觉。只有地点名字一致不代表日夜、摆设或损坏状态都一致；明确本场所需变化，避免把瞬时剧情状态永久改写到通用场景资产。

场次环境字段没有自动的“室内/日间”事实。空间类型及时段有依据时显式选择当前启用项；省略可继承明确的场景资产值，未知则留空。不要为了填满表单猜测天气或时段。

## 资产层

| 资产 | 稳定信息 | 本镜使用方式 |
| --- | --- | --- |
| 人物 `ResCharacter` | 身份、脸、年龄感、体型等稳定外貌；配音中心的角色关联（旧声音字段只读） | 凡主角与配角必配参考图（三视图与妆造细节）；复用同一人物 ID，避免跨集重复建人。 |
| 人物造型 `ResCharacterLook` | 该人物的一套服装、妆发与特定视觉状态 | 同一人物可有多个造型；镜头明确选 `lookId`，不能依赖默认造型一直不变。 |
| 场景 `ResScene` | 空间结构、出入口、材质、陈设和基础视觉设计 | 多镜复用，必要时针对机位与当下光照补充说明。建议与人物参考图协同双锚定。 |
| 道具 `ResProp` | 需要跨镜保持一致的物体外观与设计 | 仅限**独立便携道具**（长剑、茶杯、信笺、枪械等随身/可移动物品）；**附着于场景/载具的不可分离交互构件（飞船闸门拉杆、门栓、控制台舵轮等）属于场景一部分，严禁拆成孤立道具**！当镜补充谁拿着、哪只手、位置、开合/破损状态；交互设计优先遵循自然直觉，确保观众瞬间秒懂并符合物理逻辑。 |
| 关键图 `ResKeyframe` | 某个关键画面、组合人物与环境、构图或镜头规划参考 | 按用途选首帧、过程、尾帧或构图等约束；**若已有明确人物设定、道具参考图与场景图，推导关键图时必须强制严格参考这些图，严禁脱离图像通过纯文字从零重描，防止场景剧变**；**描述物理效果时只描述初始状态和结束状态，绝对不要告诉模型场景怎么动**。 |

人物稳定外貌 `appearancePrompt`、造型服装 `outfitPrompt` 与当前镜头表情/动作分开维护。凡重要角色（主角、配角，除纯路人外）都必须配备完整人物参考图（三视图与细节）；每个分镜建议至少使用人物参考图并增加场景参考图或关键图双锚定。悲伤、转头等当镜表演写入剧本，不把一次性情绪写成角色永久身份。

关键图可以来自同剧其他镜头或公共库；用前核对实际画面是否适合当前镜头。没有 `frameUrl` 的文字关键图只有规划价值，不能占用一个声称可用的参考图片槽位。

## 平台与 AI 各负责什么

平台工作台和共享业务服务负责对象归属、校验、持久化、素材归档、排序、生成任务与历史 Take 管理。内部 Agent 和外部 MCP 复用业务能力，外部 MCP 的公开能力边界以实际工具目录为准。

自动拆解中 Planner 负责分段和剧情规划，Worker 并行生成镜头剧本与视听结构，Java 做确定性合并、重排和校验，后续专用 AI 再生成图片/视频双轨提示词。拆解结果并不等于已有参考图、最终提示词或已生成的视频。

AI 负责语义理解、人物消歧、表演和视觉决策，并输出明确字段；服务端不会从“拿刀”“坐下”等字符串推断完整角色状态。读取现有事实和创作者决定，缺失信息只在确有必要时澄清。

设计场景（`ResScene`）与道具（`ResProp`）资产以及分镜交互动作时，**必须优先遵循客观物理世界与人体工学的真实性**。若小说原文或剧作剧本描写与真实性存在偏差（如夸张笔误或反力学交互），AI 必须优先遵循真实性并进行符合物理规律的合理转译，严禁盲从原文错误。
> **警惕推导反例**：原文描写“拉杆需要两个手才能拉动”，绝不能盲目推出“这一定是一个巨大的拉杆”！双手拉动反映的是机械内部阻尼与阻力大，拉杆自身尺寸必须符合人体工学抓握比例（握柄直径3–5cm），吃力感应通过角色发力表演体现，严禁机械巨物化。
>
> **关键图描述物理效果状态铁律**：创建关键图描述物理效果（如爆破、坍塌、碰撞、开闭）时，**应该描述初始状态和结束状态，绝对不要告诉模型场景是怎么动的，模型根本理解不了**！生图模型是静态采样器，向其描述动态演化过程必然导致残影与融化畸变；场景动态运动过程必须 100% 交由视频生成模型与镜头剧本驱动。

## AI 对机位与画面关系的控制法则（Camera-Frame Control）

机位（Camera）绝不是孤立的技术参数，而是决定画面（Frame）观察视点、空间透视与叙事重心的唯一纽带。AI 在进行分镜规划、生图提示词构造与视听导演时，必须精准控制机位与画面之间的四层几何与叙事关系：

### 1. 景别决定画面层次与信息载荷（Framing & Hierarchy）
机位与主体的物理距离直接决定了画面画幅的占用比例与视觉关注点：
- **远景/全景（Long/Wide Shot）**：用于建立宏观空间关系、交代建筑商铺外观与人物所处环境尺度；主体占画幅较小，重点在空间布局与环境光影，绝不在此景别苛求微表情；
- **中景/中近景（Medium/Medium Close-up）**：剧本表演与人机交互的黄金机位。画面必须完整容纳人物主要躯干、双手动作及道具的精确接触点（如手握刀柄姿态、茶杯托底动作）；
- **特写/局部细节（Close-up/Detail）**：机位极限逼近，画面只留下最关键的情绪反应（目光转动、嘴角紧绷）或道具核心咬合面（印章、锁孔、刀尖寒光）。未入画的身体或角色自然保持在画外，绝不为了同框而强行把所有元素硬塞进狭窄特写画面中。

### 2. 机位角度与 180° 空间轴线守恒（Angle & The 180° Axis）
机位俯仰与左右视点决定了画面的心理透视与空间拓扑：
- **机位视点与透视一致**：平视呈现客观真实，仰视带来威严压迫（背景垂直线条向上收敛），俯视展现全局被动；机位角度必须与背景地标、门窗透视严格吻合；
- **严格遵循 180° 动作轴线**：双人对峙或群体交互时，机位绝不能越过两人视线或运动方向的虚拟轴线。若第一镜头 A 在画左看向画右、B 在画右，下一镜头反打或切换时，画面两侧的相对方位与视线对碰必须完全一致，绝不允许机位跳跃导致左右突然翻转。

### 3. 机位运动与画面内运动的解耦与协同（Camera Movement vs. In-Frame Motion）
必须清晰区分“画面内主体的物理运动”与“摄影机自身的空间移动”：
- **主客体运动解耦**：人物朝镜头走来（在画面中逐渐放大）是主体的位移，此时机位可以是固定的（STATIC）；跟拍（Follow/Track）则是机位随主体同步位移；横摇（Pan）是机位固定原地转动角度，严禁与摄影机平移（Truck）混淆；
- **动态再构图原则**：运镜本质上是画面构图在时间轴上的平滑递进（如从手持剑柄的特写平稳拉开升起至全身对峙中景）。运镜必须有明确的画面起点、视觉引导路径与落幅终点，严禁无目的晃动。

### 4. 上下文压缩回读
- **上下文压缩主动调用工具读取**：多轮长对话中若上下文被截断压缩，对上一镜头的机位高度、透视角度或画面构图存在任何模糊时，**严禁凭空盲猜下一镜机位，必须主动调用详情工具（如 `get_shot`、`list_shots`）读回上一镜头的真实视觉参数与构图事实**，确保前后镜头机位无缝衔接。


## 配音中心

角色配音与特效配置分别在 `/dubbing/characters`、`/dubbing/effects`。角色身份表只保留基础声音的只读兼容投影。基础声音唯一且无特效，克隆保留 TTS 原声；FFmpeg 成品与原声分开保存，编辑或清空特效不调用 TTS。创建、上传、剧情选择及 MCP 调用规则见 [配音中心](dubbing-center.md)。
