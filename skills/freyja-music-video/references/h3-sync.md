# H3 时长、音轨复制与同步

当前 FREYJA + ComfyGateway + MiniMax H3 接入事实。用于请求时长、音频参考和最终拼接决策；换模型、工作流或后处理后重新核对，不能当作所有模型的统一规则。

## 请求秒数与实际视频秒数

当前网关未显式指定正数 `length` 时，按下式换算：

```text
raw = max(5, round(duration * 24))
frames = raw + (5 - raw % 17) % 17
effective_seconds = frames / 24
```

H3 原生帧数满足 `frames = 17n + 5`，原生节点也会向上对齐。网关的显式 `length` 虽优先于 `duration` 换算，仍不能用 `length=120` 绕过原生对齐。接口能接受某个数值，不等于模型能生成任意小数秒。

| 情况 | 有效帧数 @24 fps | 视频帧覆盖时长 |
| --- | --- | --- |
| 请求 5.0 秒 | 124 | `124/24 = 5.166666…` 秒 |
| 请求 5.17 秒 | 124 | 同上；5.17 是两位小数显示值 |
| 相邻可用档位 | 107 / 141 | 约 4.458333 / 5.875 秒 |
| 四段分别请求 5 秒并完整拼接 | 496 | `496/24 = 20.666666…` 秒，不能称作 20 秒 |

这里的“档位”是帧数网格，不是固定只能选 5 秒、10 秒的 UI 档。所选模型允许的时长范围、当前资源与提示词协议仍须独立检查。

保存帧数和实际帧率/时间基，或保留精确分数；展示可以四舍五入，但计算后续源入点和累计偏移不能不断累加显示值。请求时长、有效帧数、视频流时长、音频流时长、容器时长分别核对。编码尾差或音轨延长也可能影响容器时长，不能仅凭容器 5.17 秒判断多生成了几帧。

提示词按当前 `h3-prompt-writing` 的秒数及时间戳规范编写，平台要求对齐的请求字段与声明保持一致。若有效时长与请求不同，在规划和验收中明示，不能只改提示词数字、伪造尾帧对齐，或声称保存 `duration` 就已经裁好了输出。

## 音轨关系能表达什么

| `referenceType` | 选择含义与边界 |
| --- | --- |
| `fully_copy` | 请求完整源音频充当完整最终音轨。不能同时要求另加不在源音轨内的对白、配乐或环境音 |
| `partially_copy` | 只复制明确的片段/声音层，或复制后增删替换其他声音。说明保留内容及新增内容 |
| `reference` | 参考音色、风格等指定特性，不代表原曲、录音信号或原台词将原样播放 |
| `weak_reference` | 仅宽泛类别或氛围相似，不适合要求精确保留原曲的任务 |

复制关系仅在创作者明确选择后使用；已有明确选择沿用，不重复询问。音乐存在不等于用户选择 `fully_copy`。想原样保留纯伴奏再另加对白，与想完整保留已混好对白的母带，是不同的音轨设计。

当前 `minimax_h3_ref2va_official_turbo4.json` 将 `LoadAudio` 接到 H3 参考输入；最终 `CreateVideo` 的音频来自 `VAEDecodeAudio` 的模型输出，并非直接取原 `LoadAudio` 文件。因此 `fully_copy` 是生成条件与复制意图，**不是确定性的源文件直封装，不保证采样点一致、完整保真、完美对嘴或输出和源音频等长**。5 秒参考音频不会把 124 帧视频强行变成 5 秒。

`refAudios=[]` 只表示没有外部音频参考，不表示静音。`non_diegetic_music: N/A` 表示本次生成不要求配乐，不等于最终后期不能铺母带；也不能一边写 N/A 一边要求模型复制包含配乐的参考音轨。按已选择的实际路线保持全文一致：

- **生成素材，后期铺原母带**：生成侧不重生配乐，使用者确需的对白/环境音另行保留；最终由实际工具铺入原曲。若生成侧还需要音乐参考来驱动画面，先确认支持该输入与控制方式，不能把 N/A 和复制原曲混写。
- **生成侧使用带音乐的参考音轨**：按用户选择配置音频及关系，音乐段和 `overall_soundscape` 一致描述它，不再叠一条同样的音乐或对白。完整复制已混好音轨时不再要求添加源里没有的声音。

相关 BGM 开关仅在当前工具真实暴露时设置。两条路线都要验收，不能从配置项直接宣称最终已混音。

## 什么时候能直接拼，什么时候需要后期

**接受原生档位的方案**：用户允许按实际片长安排音乐/成片时，先核对连续源片段与实测输出。确认音轨没有重启、缺失、重复、突兀静音或尾差，嘴型/动作符合要求、整段时长可接受后，可使用平台顺序拼接。所选母带片段也须覆盖实际安排；只有 5 秒音频却生成约 5.1667 秒，尾部声音如何处理必须试听，不能假定模型正确补齐。

**严格保留原曲时间的方案**：原曲和台词是固定主时钟；逐镜实际成品需要通过可用的剪辑/处理工具放到母带对应区间，最终优先使用一条连续原母带。尾部多余画面只有在不截断发音、完整动作或指定尾帧时才适合修剪；切点不合适时调整镜头/素材，不能盲目一刀切。替换音轨也不能修复已经错拍的嘴型。

裁帧、调视频速度、改帧率、拉伸音频是不同操作。124 帧改为 24.8 fps 虽可得到 5 秒，却改变视频播放时间与表演节奏，不能默认这样做。未经允许不拉伸原曲、不删词、不无条件丢尾帧；有真实需求和可用工具才选择处理方式。交付精度以实际帧率和音频采样率可表达的时间为准，不承诺任意小数秒都能逐帧精确表示。

平台当前顺序导出会归一化到 30 fps 并重编码音频，仍按实际整段视频拼接；它不是源媒体无损直连，也不会自动把每个约 5.1667 秒片段裁成 5 秒。归一化或补帧之后重新探测，不能继续用原始 24 fps 的帧数解释成片。

## 依据与维护

- 网关换算：仓库 `comfy_gateway/schemas.py` 的 `calculate_minimax_length`。
- 参考工作流：`comfy_gateway/comfyUIApi/minimax_h3_ref2va_official_turbo4.json` 的参考音频输入和最终音频解码路径。
- [ComfyUI H3 原生节点](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_minimax_h3.py)：`FPS`、`align_frame_count`、`temporal_shape`。
- [MiniMax H3 官方参考提示词规范](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/ref-en.txt)：音频复制/参考语义；实际写卡以平台当前发布版为准。
- 拼接行为：`src/main/java/com/astra/freyja/service/mediaexport/ShotVideoConcatService.java`。这些路径用于维护者核对，不要求平台 AI 拥有仓库文件权限。
