# 默认宠物新增帧与放慢播放验证（2026-10-12）

以下为首轮减速的历史记录。用户再次反馈细节抖动后，继续降低了播放速度；当前周期见 [后续减速验证](slower-playback-validation.md)。

默认形象新增 16 帧动作图集。最初按此前周期播放时，用户反馈动作有「抽搐」感，因此按用户要求将默认播放速度再降低 50%。当前保留原动作，延长每轮时长；没有改成固定人物原画的补间方案。用户上传的社区宠物沿用原有帧数和速度。

## 实际播放

通过 Chrome + Playwright 在生产构建预览及 WSL Docker 页面采集 DOM 帧变化。默认配置的九种动作与右下角宠物均实际访问到 16 张画格，部署后测量如下：

| 动作 | 目标周期（毫秒） | 实测周期（毫秒） |
| --- | ---: | ---: |
| 待机 | 6400 | 6404 |
| 向右移动 | 4240 | 4236 |
| 向左移动 | 4240 | 4236 |
| 招手 | 2800 | 2801 |
| 完成 | 3360 | 3358 |
| 遇到问题 | 4880 | 4880 |
| 等待处理 | 4040 | 4039 |
| 工作 | 3280 | 3281 |
| 思考 | 4120 | 4122 |

待机活动约 3.2 秒后停顿约 3.2 秒。轻动作往返共 30 个播放阶段，但只有 16 张源画；左右移动为 16 个阶段。不会把阶段数写成新增原画帧数。

## 行为与兼容

- 点击宠物打开/关闭 Freyja agent 聊天，左右拖动切换对应动作，通过。
- `prefers-reduced-motion: reduce` 下全部预览及宠物静止于第 0 帧，通过。
- 模拟 `document.hidden` 和 `visibilitychange`：隐藏两秒期间帧不变，恢复后继续变化，通过。
- 拦截增强图集请求使其失败，播放器回退原始 8 列图集及既有周期，通过。
- 在浏览器响应中模拟社区 v1/v2 宠物，分别使用 9/11 行图集，均保留 8 列、标准帧数及既有周期，通过。未将模拟配置保存到服务器。
- 浏览器未出现未处理异常；配置读取结果前后哈希一致；所有非 GET 后端请求被记录并隔离，记录为 0 次。

测试浏览器将会话与提醒列表隔离为空，以免打开聊天时读取或标记用户历史。原始采样与截图保存在 `logs/agent-pet-smooth-*`；可版本追溯的汇总在 [smooth-playback-validation.json](smooth-playback-validation.json)。
