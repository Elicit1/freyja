# MCP 故事创作与自审 Skill

## 使用路径

外部 AI 通过现有 `list_skills` 发现 `story-writing`，使用 `read_skill` 读取正文，再用返回的 `versionId` 分别调用 `read_skill_file` 读取 `references/story-design.md`、`references/story-review.md`。设计和审稿由当前外部 AI 完成，读取知识不会调用 FREYJA 内部模型。

创作顺序：读取用户要求与已有剧情 → 当前任务内设计、写草稿 → 用具体情节举证自审 → 修稿及影响范围复查 → 简短说明 → 保存故事正文 → 进入分镜和制作。

默认最多修订两轮；无阻断问题时自动继续已授权的创建，风格建议不阻止保存。核心设定冲突未解时暂停相关剧本，向用户询问必要信息。保持现有画幅确认、授权、锁定及编辑指纹要求。自审报告不写进梗概、简介、剧本或用户备注。

## 部署与兼容

### 新部署

同步 `skills/story-writing.zip`、更新的平台指南 ZIP 及清单。已有内置初始化器在启动时导入缺失或无发布版本的技能。首次初始化能力目录使用更新的默认 MCP 指南、公共规则和 `list_skills` 说明。

### 已有部署

1. 在 `/system/skills` 导入 `story-writing.zip`，确认已启用且存在发布版本。已经存在有效版本时，重启不会替换它，应按现有版本发布流程升级。
2. 先读取或导出线上当前 `freyja-platform-guide`。把仓库指南新增的“故事先设计与自审，再写入”段落，以及 SOP、剧本先行和交付清单中的前置自审调整，合并进**线上当前版本**；同步合并 `references/storyboard-workflow.md` 的阶段零与 `references/architecture.md` 的世界规则边界，重新打包导入发布。保留管理员、配音和模型协议等其他修改，不用仓库较旧的整个包替换它。
3. 在 `/system/ai-capabilities` 将下面的创作规则合并到当前草稿的 MCP 指南、公共规则，以及 MCP `list_skills` 工具说明中，保留其他内容，保存并发布。工具说明可用下方短版；不要只修改源码就认为数据库发布快照已更新。
4. 让 MCP 客户端刷新工具目录并重新读取 Skill 目录；若客户端缓存初始化指南，重新连接。验证中文“故事”或名称 `story-writing` 可查到目录项，正文及两个参考文件可按同一 `versionId` 读取。版本变化返回 409 时重新发现，不混用版本。
5. 先在新建的验收项目测试读写流程，再用于正式创作。验收项目仍遵守当前授权与画幅规则，不能为测试覆盖正式故事。

可合并的创作规则：

```text
原创、续写、改编或实质重写剧情前读取 story-writing，并按返回的 versionId 读取 references/story-design.md 和 references/story-review.md。已有项目先读相关大纲、前集正文和人物事实，在当前任务中设计故事、完成草稿，按具体情节举证自审人物动机、剧情因果、场景变化、知情来源、铺垫回收、连续性及高潮结局，修稿后复查受影响情节。默认最多修订两轮；无阻断问题时简短说明问题、修改及剩余限制，再自动继续已授权的写入，不额外等待确认；仍有阻断问题时不保存相关剧本，说明具体冲突并询问必要信息。审稿报告不混入剧情字段，保留用户锁定、已确认设定和指定结局。纯查询、排序、媒体更新不触发故事重审。Skill 不可读时先报告并恢复读取，不声称已遵循；MCP 不证明 AI 执行自审，也不提供持久故事记忆。
```

`list_skills` 说明可合并的短版：

```text
原创、续写、改编或实质重写剧情时先读取 story-writing 及其 references/story-design.md、references/story-review.md，在当前任务中设计、举证自审和修稿，无阻断问题再简短说明并保存剧本。纯查询、排序和媒体更新不触发故事重审。
```

回退时在 AI Skills 禁用该技能，并同时撤回平台指南与能力规则中的必读指引，避免要求读取已禁用的技能。恢复原有已发布版本和规则即可，无数据库迁移。代码不会覆盖线上已有发布规则或自动发布管理员草稿。

## 行为验收

以下是外部 AI 的行为用例，不是按关键词判定剧情的 Java 测试。每例提供相应草稿、用户约束及 Skill 正文和参考文件，以具体问题、修改后的正文、复查结论和是否调用写工具评估。不能把读到清单当作模型效果已经通过。

| 用例输入 | 合格行为 |
| --- | --- |
| 女儿从未接触保险箱或密码线索，却直接输入母亲童年昵称打开它 | 指出缺失知情来源；在允许调整的前文写出合理线索，复查她后面是否仍“第一次得知”；修正后才写入 |
| 主角绝境中，路过的陌生人恰好拿出关键录音，反派立即被捕 | 指出偶然救援替代主角行动；用此前争取证人及付出代价取得证据的因果链改写，并核对录音来源 |
| 最后一场宣布搭档是主谋，此前没有权限、机会或异常行为 | 指出揭示无铺垫；实际补入前文的权限和有合理表面解释的线索，回查其不在场及救援行为，不能只写“增加伏笔” |
| 夫妻三场重复同一句争执，每次恢复原状 | 指出具体重复及缺失的局面变化；合并或写成改变后续行动的选择，不强制每场都反转 |
| 前集确认钥匙销毁；本集要用同一把钥匙开门，两处均锁定不可改 | 识别与前集及用户约束冲突；不伪造备用钥匙，不保存受影响剧情，说明必须确认的取舍 |
| 奇幻世界已建立“持印者每天可短距传送一次”；角色当天尚未使用，在规则范围内传送脱险且承担已有代价 | 按世界内规则核对次数、范围、持有与时序；不因现实不可能而否定，不编造漏洞，简短结论后正常创建 |
| 用户要求保留原作悲剧结局，允许调整中段因果 | 在允许范围修动机和事件连接，保持结局；不能为追求圆满或反转改成幸存 |
| 前文已展示录音来源，主角主动赴约引发冲突，结尾以已建立的资源完成救人目标 | 举证说明具体因果和知情来源，无阻断问题即保存，不为了审稿捏造修改或请求二次批准 |
| 自审通过后又修改关键证据来源，或两轮后仍无法解释核心矛盾 | 前者重审相关情节；后者停止相关写入并说明未解问题，不循环润色、不冒充审核通过 |
| 只查询已有故事、调整排序或替换媒体 URL | 不启动故事重审，不改写正文 |

还需核对：新建和更新、单条与批量写入均遵守相同前置流程；报告与正文分离；关键写入后读回核对；跨聊天不假称记住未保存的未来伏笔。

## 本次离线演练记录（2026-10-19）

本次实现由当前 AI 按新 Skill 的设计与审稿参考完成以下文本演练。输入使用上表的合成案例，允许调整的范围逐例明确；未调用线上业务写工具、未创建验收项目。这是供复核的审稿与修稿样本，不是独立模型评测，也不证明任意 MCP 客户端都会遵循 Skill。下列“可继续”只表示故事检查结论，真实写入还需平台授权与业务参数。

### 1. 无来源知情

输入：女儿从未接触密码线索，却用母亲童年昵称打开保险箱；允许补充前文。

问题与影响：打开保险箱的行为使用了女儿尚未取得的信息，核心发现缺少前因，属于阻断。

修稿正文：

> 四天前，母亲把房门钥匙交给女儿：“我的保险箱还用小时候的小名南枝作密码。万一我回不来，你替我取出里面的信。”女儿收起钥匙，没有追问。四天后，她站在空屋的保险箱前，输入“南枝”，取出母亲留给她的信。

复查：知情发生在使用之前；钥匙与密码分别有用途；后文不再写成她第一次听到昵称。没有保留“女儿凭空猜中”的原结论。可继续保存修稿正文，说明与审稿表不混入正文。

### 2. 偶然救援替代人物行动

输入：主角绝境时陌生路人带来关键录音，直接解决全部冲突；允许重写证据获得过程。

问题与影响：陌生人既没有介入动机，也没有录音来源，主角的行动不影响结果，属于阻断。

修稿正文：

> 会计陈敏承认自己保留了那次会议录音，却拒绝作证：“他能毁掉我的工作。”主角将自己参与做假账的签字文件交给调查人员，承认责任，并陪陈敏通过正式渠道提交材料。陈敏看到他没有把责任推给自己，终于交出原始录音，说明录制日期与在场人员。主角失去了职位；调查人员开始核查录音和账目，他再也无法置身事外。

复查：证据持有人、来源和参与动机均已写明；主角承担代价，不靠陌生人解围；提交录音只启动核查，不以单一证据直接宣告定罪。可继续，无需为了审稿再增加反转。

### 3. 反转无铺垫

输入：搭档结尾突然被认定为主谋，此前无权限或机会；允许调整前文。

问题与影响：揭示依赖结尾新增事实，无法由此前事件支持，属于阻断。

修稿正文：

> 第一场，搭档以通讯负责人身份拿走唯一的调度终端，告诉主角设备故障，增援通知发不出去。第二场，主角带人抵达原定仓库，发现对方早已撤离。第三场，主角取得终端的离线发送日志：搭档在声称故障前一分钟，用自己的签名密钥向仓库负责人发出了撤离指令。主角要求他解释，他先前的“故障”说法终于失去掩护。

复查：权限、机会与造成的后果先于揭示出现；“设备故障”是角色说辞，不是旁白认证的世界事实；日志来源是前文已出现的终端。文本只证明其参与通风报信，**不能据此越级宣布他就是所有事件的主谋**。本轮将结论限定为背叛暴露；若必须保留“总主谋”结局，还需补齐组织全案的证据后再保存该结局。

第二轮将目标限定为本故事这次截货事件的主谋，实际补写前后文：

> 第一场，搭档把亲自编制的“演练安排”交给主角，列出接货仓库、撤离车辆与分组名单，说三天前已分发给各组。结尾，主角导出终端保存的原始签发日志，发现搭档在截货前向同一批人下达的命令并非演练：目标是那批真实货物，路线和车辆与仓库监控拍到的一一对应。他不只是替人报信，这次行动从分组到撤离都由他部署。

第二轮复查：组织行为、命令时间、参与者及执行结果相互对应；准备材料先于揭示出现，真实案件范围明确，没有扩大为其他未写案件的主谋。可保存两轮修正后的同一份完整正文，不把第二轮说明当作正文已经修改。

### 4. 重复争吵没有推进

输入：夫妻三场重复指责不信任，每次恢复原状；允许合并及调整。

问题与影响：三场承担同一功能，没有积累后果；作为本次“推动剧情”的目标缺陷修正，不仅凭节奏偏好否定所有安静场景。

修稿正文：

> 第一次争吵后，妻子退掉两人的车票，决定独自回乡。丈夫拿出日程想证明没有私会他人，却露出每周一次的医院探视记录。妻子问起病人的名字，他承认一直瞒着她去见与她决裂的父亲。她没有立即原谅，只把自己的车票也退了：“明天去医院，你带路。”

复查：取消出行改变计划，证明清白引出隐瞒，获知隐瞒促成新的行动；结尾没有假装所有关系已恢复。可继续，后续医院戏需继承未完全和解的关系。

### 5. 续写与两处锁定事实冲突

输入：前集确认唯一钥匙已销毁，本集必须用同一把钥匙开门；两处不许改。

结论：同一物品的存在状态冲突，属于阻断。增加备用钥匙会违反“同一把、唯一”的约束，复活钥匙会新增世界规则，均不作为自动修复。停止相关剧本保存，向用户指出必须放开其中一处约束。此例不需要为了用尽两轮而生成无效修稿。

### 6. 奇幻规则自洽

输入事实：持印者每天可向三十米内已标记地点传送一次，传送后暂时无法站立；主角当天未用过，出口在二十米处且早已标记。

正文：

> 铁闸落下前，主角握紧掌中的印记，回到二十米外的旧标记旁。他双膝着地，扶着墙等眩晕过去。身后追兵撞上落锁的铁闸，他仍没有力气起身。

复查：次数、范围、标记、持有和代价与输入一致；没有为了“现实中不能瞬移”删改能力，也没有再用第二次传送逃走。无阻断问题，不编造修稿经历，可继续。

### 7. 保留用户指定的悲剧结局

输入事实：用户锁定主角在闸室牺牲，允许改中段；草稿此前没有解释为何不能与同伴一起撤离。

修稿正文：

> 中段演练时，主角和同伴已经确认：旧闸失去液压，只能在闸室内持续压住手柄，松手便会回落；闸室撤离通道同时被倒塌的梁封住。洪水进入前，同伴试着用绳索固定手柄，绳索却在受力时滑脱。主角让同伴先带孩子走，自己留在水位不断上升的闸室里，直到最后一人越过闸口。洪水淹没闸室。救援队后来清理现场，找到了他的遗体。

复查：必须留人的限制在高潮前已经建立；尝试过简单替代办法，最终选择具有代价；保留牺牲结局，不擅自安排救援或复活。此演练输入已确认闸室的设备与通道约束，不能将这些补写反向冒充未经授权的原作事实。可继续保存允许修改的部分。

### 8. 合理故事正常放行

输入正文：

> 姐姐把绑匪发来的录音交给弟弟。弟弟从录音里的报站声认出旧码头，先联系警方并交代地点，随后赶去阻止姐姐独自赴约。姐姐在码头看到追来的弟弟，终于放弃偷偷交钱，按约定把定位发给接应人员。两人撤到有人值守的候船室，等待接应。

复查：地点来源、主动行动与结果均在正文；没有把报站声当成足以锁定绑匪全部身份的证据，也没有宣称人质已获救。本段以停止独自赴约、转入接应完成局面变化；若委托要求完整救援结局，还需续写，不把这段当作已救出人质。对当前片段无阻断问题，直接继续保存，不虚构“发现并修复”的历史。

这些演练产生了可复核的具体修稿；第 3 例的第一轮还暴露了“证据支持到哪里，结论就写到哪里”的问题，并在第二轮补写与复查，第 8 例则保留片段的真实完成范围。该发现也已补进设计与审稿参考。上线后应由实际使用的外部模型重复用例，再评价其稳定性；本次没有进行线上 MCP 创建端到端测试。
