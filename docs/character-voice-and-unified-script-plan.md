# 角色声音与统一分镜剧本：实施方案及验收记录

更新日期：2026-10-14。状态：代码已修正，验证结果见本文末尾；真实视频模型生成效果仍需人工验收。

## 1. 业务边界

- 创作者只在 `scriptContent` 编写镜头动作、对白、画外音、旁白和内心独白；`actionDescription` 仅用于概览。
- 角色母音只在人物资产中设计或上传。分镜通过显式 `refAudios` 引用已有素材，不维护独立 TTS 生成入口。
- `VOICE_TIMBRE` 只借鉴声线；母音试音文字不是本镜台词。`DIALOGUE_REUSE` 仅用于创作者明确选择的本镜授权录音。音效参考按自己的用途处理。
- 不使用母音与静音是不同要求。静音等自然语言要求交给 AI 理解；Java 不解析关键词、冒号、角色名子串或代词来推断。
- 画面出场人物与声音人物独立。人物被提到、仅画外说话或充当旁白，不构成出场角色。

## 2. 唯一事实源与派生声音结构

Worker 的输出 Schema 不再含 `dialogue`、`dialogueSpeaker`、`voiceover`。必须把全部原文声音内容写入 `scriptContent`；`characterIds` 只明确声明实际画面出场人物。

提示词 AI 从本次剧本提取只读 `speechLines`，每项含：

| 字段 | 约定 |
| --- | --- |
| kind | ON_SCREEN_DIALOGUE / OFF_SCREEN_DIALOGUE / VOICEOVER / INNER_MONOLOGUE |
| characterId | 明确的角色资产 ID；不明或匿名旁白为 null，不按列表顺序猜测 |
| speakerName | 明确说话人名称，可为 null |
| text / language | 逐字原文台词及 AI 明确识别的原声语言 |
| dialogueTag | 完整 `<d>...</d>` 标签，必须逐字包含原文并出现于视频提示词 |
| audioIndex | 显式使用的 Audio N；不用参考音频时为 null |

无口语声音时必须返回 `speechLines: []`。缺少该结构的旧外部 AI 结果应使用最新任务 Prompt 重新生成。前端提供只读台词核对列表，修改台词仍回到统一剧本。新任务随剧本、导演计划和素材上下文重新生成，不把旧派生列表当成剧本事实。

Java 只校验枚举、原文逐字包含关系、协议标签、素材编号和明确的说话人绑定；不判断自然语言是否包含对白。音色参考绑定不一致、音效充当对白母音、缺失或越界的引用必须报错。

## 3. 音频选择状态与默认行为

使用现有 `ref_audios_json` 区分状态，无新增数据库列：

| 存储状态 | 展示字段 | 行为 |
| --- | --- | --- |
| null / 未配置 | refAudiosConfigured=false | 素材选项加载完成后可提供首次默认角色母音 |
| [] | refAudiosConfigured=true | 明确不使用参考音频；重新打开也保持空 |
| 非空列表 | refAudiosConfigured=true | 保留顺序、用途、角色绑定与 URL 快照 |

生成请求始终传递当前 `refAudios`，包括空列表；服务端只有在字段省略时才读取保存的快照。任务提交前冻结音频清单。保存空列表必须成功写入 `[]`，序列化失败不能返回成功。

首次默认候选超过三个音频槽位时提示创作者明确选择，不自动取前三人。追加角色不会覆盖已保存的选择。既有分镜引用保留 URL 快照；更新人物母音后，创作者可以显式替换分镜参考，历史 Take 保持原快照。

## 4. 元数据与实际渲染

- 未知时长、未知语言保持空值；前端不写死 3.5 秒，Java 不按文本长度估算音频时长。
- 浏览器测量失败展示待检测；服务器通过 FFprobe 验证实际音频字节及音频流。
- H3 协议约束集中在 `ShotAudioReferenceValidator`：最多三段、单段 2–15 秒、总长不超过 15 秒。所选模型的已配置 `maxAudios` 也必须遵守。
- 超限、媒体读取失败、时长探测失败均明确报错，不截断、不跳过素材、不继续生成失配视频。
- `AiImageApiServiceImpl` 只发送显式音频引用，不再读取旧 `DramaShot.audioUrl`。
- 音色参考、授权录音和音效各按显式 `usageMode` 处理，不能强制把第一条音频当成角色母音。
- 人物声音设计的提供商和模型根据已配置模型列表选择；移除名称正则猜测、硬编码模型优选和服务端自动重定向。

## 5. 历史数据与旧链路退出

`UnifiedShotScript` 仅做确定性格式包装，完整附加历史对白和旁白并标注请核对，不尝试语义去重，也不替未知对白猜说话人。

读取分镜详情、大纲、MCP 或内部制作上下文时可看到统一内容。保存明确编辑的统一剧本或执行局部更新时完成迁移，旧字段与统一文本在同次 UPDATE 中处理。排序、移动镜头组、渲染状态等稀疏更新不会清空尚未迁移的旧对白。

Redis 历史拆解草稿及服务器保存的旧提示词任务输入在读取时按旧 JSON 字段结构迁移，不丢弃旧台词。新 Worker / 新请求不再输出或写入旧字段。

已删除分镜/整集 TTS Controller、服务、DTO、前端 API、任务创建入口及渲染弹窗中的旧配音入口。新 REST 写入明确拒绝旧字段，MCP 写入 Schema 不暴露它们。旧任务枚举仅保留用于读取历史记录，ORM 旧列仅用于迁移及并发校验。

可选批量迁移脚本：`src/main/resources/sql/migrate_unified_shot_script.sql`。脚本先备份原剧本、对白、旁白和旧音频 URL，再执行可重复迁移；本次未对真实数据库执行。未执行脚本时，应用仍支持逐镜迁移。不要在现有数据库重跑含 DROP/REPLACE 的初始化脚本。

## 6. 提示词与契约同步

Java 默认 Worker 提示词、根初始化 SQL、Docker 初始化 SQL、MCP 指令与读写 Schema 已同步。统一剧本/结构化声音契约也会追加到运行时可配置提示词末尾，因此现有数据库或 Redis 缓存中的旧提示词无需通过破坏性重新初始化更新。

FL2VA / Ref2VA 均要求 `speechLines`，原声台词保留原语言；英语要求适用于画面、摄影与声场描述。旧重复 H3 校验方法和冒号检测已移除，使用实际生成及外部解析共用的校验路径。

## 7. 验收用例

1. 老分镜仅有独立对白/旁白：打开时完整显示于剧本，核对保存后旧字段退出；再次打开无重复追加。
2. 仅修改老分镜备注：历史声音不丢失。排序或移动镜头组也不清空历史对白。
3. 四个角色有母音：默认策略要求选择；服务端不会截取前三条。
4. 取消最后一段参考并保存：本次请求、重新打开和下次生成均为空，不恢复旧音频。
5. 角色改母音：现有分镜及历史 Take URL 不被隐式替换，可显式重新选择。
6. 剧本写“张三不在现场”“李四想起她”：未声明的角色不会被 Java 加入出场列表。
7. 写“时间：深夜”：不会被 Java 推断成对白；画外对白和旁白可独立提取并核对。
8. 母音为英语、本镜台词为中文：用途和原声语言独立，禁止复制试音旧台词。
9. 已存旧 audioUrl，但参考列表为空：新视频请求不含隐藏旧音频。
10. 客户端伪报 3 秒、实际音频 20 秒：渲染前拒绝；无法测量时保持未知并明确报错。
11. 外部 AI 输出缺少 speechLines 或台词标签/说话人绑定不一致：实际解析流程拒绝。
12. 19 位 ID 在默认选音色、请求与响应中完整保留。
