# 分镜当前视频打包下载设计

状态：已实现首版，接口与部署说明见 [API 文档](shot-video-export-api.md)。日期：2026-10-16。

## 1. 功能与入口

增加“视频打包下载”，允许选择一个短剧，再按“分集 → 场景 → 镜头组 → 分镜”勾选范围。可一次导出整部短剧，也可混选多个分集、场景、镜头组和单镜。

入口放在剧作工作台工具栏，与“批量视频渲染”并列。进入时默认当前短剧，同时提供短剧选择器；更换短剧清空树选择和预检结果。任务中心支持查看历史打包任务、进度和下载结果。

导出的是每个分镜**提交时当前绑定的视频**，依据 `DramaShot.videoUrl` 和 `currentVideoTakeId` 冻结快照。每镜最多一个视频；历史 Take、当前未选中的新版、后续渲染结果均不自动加入。

打包只读取已有视频，不调用 AI、Comfy Gateway 或 FFmpeg，不占用渲染串行队列，不修改分镜当前绑定。

## 2. 交互

弹窗采用左侧选择树、右侧导出清单：

```text
视频打包下载                                      [选择短剧 ▼]
┌──────────────────────┬─────────────────────────────────────┐
│ 搜索分集 / 场景 / 镜头组 │ 已选 26 镜 · 可导出 23 · 无视频 3       │
│ ☑ 第 01 集  12/14       │ 分集 / 场景 / 镜头组 / 分镜            │
│   ☑ 场景 01            │ 当前视频版本 · 预计时长 · 检查结果      │
│     ☑ 镜头组 01        │ S01  Take 3       5s      可导出       │
│       ☑ S01            │ S02  当前绑定     4s      可导出       │
│       ☑ S02            │ S03  —            —      无视频       │
│   ◩ 场景 02            │                                     │
│ ☑ 第 02 集             │ [✓] 跳过未绑定视频的分镜               │
└──────────────────────┴─────────────────────────────────────┘
                         [取消] [检查] [生成 ZIP（23 个视频）]
```

- 父节点支持全选、半选；混选按分镜 ID 去重。每个节点显示“已绑定视频数 / 分镜数”。
- 没有镜头组的分镜直接显示在场景下；无法归属现存上级的分镜显示在明确的“未归组”节点，不静默遗漏。
- 搜索仅过滤展示，不改变已选范围；“全选整个短剧”和“全选搜索结果”须分开标注。
- 预检表显示位置、分镜名、当前 Take 编号或“历史直接绑定”、时长、大小是否已知、导出状态。没有可靠大小时显示“未知”，不伪造预计容量。
- 默认跳过没有视频的镜头，并明确显示数量；可切换为“缺失视频时禁止创建”。选择变化使预检失效。
- 提交后立即返回任务，显示“后台打包中，可以关闭窗口”。关闭窗口不取消任务。
- 成功后显示 ZIP 大小、有效期和“下载 ZIP”；部分成功还展示失败清单及“按原快照重试”。不自动在后台弹出浏览器下载。
- 使用现有 `/ws/task-center` 推送进度。仅在打开详情、操作完成、WebSocket 重连时读取快照，没有定时刷新。

## 3. 选择与视频版本规则

| 情况 | 决策 |
| --- | --- |
| 勾选短剧 / 分集 / 场景 / 镜头组 | 服务端展开为有序分镜集合 |
| 同一分镜从多个父节点选中 | 仅导出一次 |
| 不同分镜引用相同视频地址 | 分别保留文件，维持镜头与文件一一对应 |
| `videoUrl` 非空、没有 `currentVideoTakeId` | 兼容历史直接绑定，按当前 URL 导出 |
| 存在 `currentVideoTakeId` | 校验 Take 存在、归属当前分镜且 URL 与当前绑定一致；不一致则阻塞，禁止擅自修复或换版本 |
| `videoUrl` 为空 | 标记 MISSING_VIDEO，不从历史 Take 自动挑选 |
| 分镜新任务正在排队 / 渲染，已有旧视频绑定 | 可导出当前已绑定视频，并提示“不会等待新结果” |
| 预检后换了 Take、视频地址或层级顺序 | 创建返回 409，要求重新检查；不能悄悄换成另一版 |
| 创建后更名、重排、换 Take 或解绑 | 不影响该任务冻结的清单、路径和来源 |
| 创建后源对象被删除或不可读 | 记录读取失败，不使用其他版本补位 |

所有入参层级必须存在且属于所选短剧，逻辑删除数据不参与新任务。客户端只传业务 ID 和选择范围，不接受客户端指定源视频 URL、对象键或 ZIP 内文件路径。

排序遵循工作台叙事顺序：分集、场景、镜头组、分镜逐级按 `sortOrder → 业务序号 → id` 排序；空排序值、空组及异常层级采用固定顺序。禁止依赖数据库返回顺序或只按分镜编号全局排序。

## 4. ZIP 内容

```text
短剧名称/
  001_第01集_集名/
    001_场景01_场景名/
      001_镜头组01_组名/
        0001_S01_分镜名_Take03.mp4
        0002_S02_分镜名_当前绑定.mp4
      002_未归组/
        0003_S03_分镜名_Take01.webm
  002_第02集_集名/
    ...
  导出清单.csv
  manifest.json
  失败清单.csv                 # 有缺失或失败项时生成
```

目录与文件前的序号按冻结清单分配，保留原顺序；选择子集也保留其原始位置编号。生成名称时去除路径分隔符、控制字符和 Windows 非法文件名字符，限制目录与完整路径长度；裁剪后冲突时附加分镜 ID，最终路径必须唯一且不能越出 ZIP 根目录。

保持原视频字节、编码、分辨率及音轨；根据受控对象元数据确定扩展名，不把所有视频强行改为 `.mp4`。首版不提供拼接、转码、字幕或单独音频导出选项。

清单记录：导出序号、层级 ID 与名称、分镜 ID 与名称、Take ID / 编号、包内相对路径、实际文件大小、校验值、结果和失败原因。ID 一律输出字符串；CSV 使用 UTF-8 BOM，对名称等自由文本处理表格公式注入。

对外清单不写入内部 MinIO 地址、访问密钥或签名 URL；后台保存可解析的来源快照用于追溯。

## 5. 后端流程与不轮询调度

1. `selection-tree` 返回带可导出计数的选择树。`preview` 展开选择、去重、排序，解析当前绑定，生成条目清单和 `previewHash`，不下载视频。
2. `create` 在一个短事务中按固定 ID 顺序锁定选中分镜，重新校验层级、Take 关系和预检摘要，保存任务及全部条目快照。事务内不执行 MinIO / HTTP 读写；事务提交后发出队列事件。
3. 独立文件导出消费者按创建顺序领取任务。首版全局同时打包一个任务，使用独立执行器与独立 MySQL 调度锁，不能复用 `RenderDispatchCoordinator`、视频渲染锁或共享渲染线程池。
4. 每条目从可信媒体存储读取源视频，逐镜完成读取和校验，再加入 ZIP；进度按字节和文件数推送。完成一项直接处理下一项，不定时查询上游状态。
5. ZIP 完成后上传 MinIO 导出目录，确认对象可读取、大小匹配，才将任务发布为可下载；打包中或上传中的半成品不能下载。
6. 当前任务结束后直接执行下一任务。创建、取消和重试的提交事件及应用启动恢复唤醒消费者；多实例通过 Redis Pub/Sub 转发通知。空闲即停止，不设置数据库扫描定时器。

持久化状态使用 MySQL，Redis 仅承载事件通知和现有任务中心能力。消费者取得全局互斥锁后再恢复残留在途任务；恢复采用新的执行令牌和对象路径，最终状态通过令牌及 revision 条件更新，防止旧线程晚到覆盖。未完成 ZIP 不续写，重新从原快照构建；不能修改为恢复时的最新视频。

任务状态：`QUEUED → PACKAGING → UPLOADING → SUCCESS / PARTIAL_SUCCESS`；另有 `FAILED`、`CANCELLED`。过期是文件可用性状态，详情返回 `downloadAvailable=false` 和 `expiresAt`，不把已完成任务伪装成打包失败。

任务中心：`sourceType=SHOT_VIDEO_EXPORT`、`category=FILE_EXPORT`、`resumeAction=SHOT_VIDEO_EXPORT`。页面展示“已处理 8/23 个视频，已读取 430 MB；当前 S08”；大小未知时不展示虚假字节百分比。映射 `PACKAGING` / `UPLOADING` 为任务中心 RUNNING，并在 `currentStage` 保留具体阶段；进度单调递增，只有产物就绪才能达到 100%。

## 6. 存储、读取与容量

- 新增独立媒体来源解析器，复用 MinIO 客户端。优先将应用已持有的视频地址解析为经过校验的 bucket / objectKey；按 URI 结构匹配配置端点和桶，不照搬现有 `contains(bucket)` 的字符串猜测方式。
- 原始对象引用、对象大小、ETag、可用时的 versionId 均进入快照。现有生成视频采用唯一对象名；若未来允许覆盖同名对象，须使用版本化读取或一致性条件，变化时失败，不能导出替换后的字节。
- 仅兼容服务端已绑定、来源可验证的历史媒体。无法归属可信存储的地址在预检中明确阻塞；后续若支持外部来源，需单独定义来源允许列表及重定向校验，不提供任意 URL 代理。
- MP4 等已压缩视频使用 ZIP STORED，JDK ZIP64 支持大文件 / 大包，不额外引入压缩依赖。
- 单镜先流式下载到任务专属临时文件，计算大小和 CRC / SHA-256，再写入 ZIP。这样源读取中断不会在“部分成功”的 ZIP 里留下损坏视频。内存只保留固定大小缓冲区，禁止整包 `byte[]` 或 `readAllBytes()`。
- 同一时刻本地只保留当前源文件和正在构建的 ZIP，源条目写入后即删除；支持可配置最大镜头数、单文件大小、整包大小、最小剩余磁盘空间及下载超时，实际读取时持续执行限额。
- 建议首版默认最多 1000 镜、单文件 4 GiB、整包 20 GiB；可通过配置调整，不能继承批量渲染的 200 镜业务限制。容量上限包含 ZIP 与清单开销，预检只在大小可靠时给出容量估计。
- 产物使用独立私有导出桶或明确受控的私有存储空间，路径 `shot-video-exports/{taskId}/{attemptToken}/package.zip`；默认保留 24 小时，通过存储生命周期清理。不要将导出包放入默认公开媒体桶后仅靠 UI 隐藏链接。
- 下载时后端校验任务和产物可用性，返回有效期 10 分钟、带 UTF-8 下载文件名的预签名链接，并确保签名可访问期不超过产物剩余保留期。浏览器原生导航下载，避免 Axios Blob 将数十 GB 压入内存；链接失效后用户可重新获取。
- 临时文件在成功、失败和取消时清理；进程中断残留在启动恢复及后续任务开始时按归属清理，不依赖周期轮询。仅允许清理专属临时根目录内已验证的任务路径。

## 7. 失败、取消、幂等与重试

默认采用部分成功策略：预检缺失项按用户选项跳过；执行时某条目明确不可读、超限、对象变化或读取超时，清理该临时文件并记录失败，然后继续其他条目。

至少一个视频成功时生成有效 ZIP，存在失败或缺失则为 PARTIAL_SUCCESS，并包含失败清单；没有任何成功视频则 FAILED，不提供空视频包。ZIP 写入、磁盘容量、产物上传或整体一致性失败属于整项失败，不能发布残缺 ZIP。

取消时移除尚未执行任务，或中断当前源读取 / ZIP 写入 / 上传，删除当前尝试半成品，保留取消记录。完成和取消使用数据库条件更新竞争，已完成任务返回“任务已完成”，不能同时出现成功可下载和取消成功。

`clientRequestId` 建唯一约束；相同标识且内容一致返回原任务，不重复打包，内容不同返回 409。原任务产物过期仍返回原任务及过期说明，不隐式创建新任务。

“按原快照重试”新建带 `retryOfTaskId` 的任务，复用完整冻结清单重新构建整个包，保持可用镜头齐全。若需要最新绑定或补入后来生成的视频，重新选择并预检创建新任务。下载重试只重新签发链接，不重新打包。

## 8. API 草案

业务接口沿用 `R<T>`，前缀 `/drama/shot-video-exports`。所有 ID 使用字符串传输。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /selection-tree?dramaId=...` | 层级选择树，含 shotCount / videoCount |
| `POST /preview` | 解析范围与当前视频绑定，返回有序清单、缺失 / 阻塞数量及 previewHash |
| `POST /` | 幂等创建持久化任务，立即返回 QUEUED |
| `GET /?dramaId=...&current=1&size=20` | 当前短剧的打包历史 |
| `GET /{id}` | 汇总、阶段、计数、文件大小、有效期与可下载状态 |
| `GET /{id}/items?current=1&size=50` | 分页查看冻结条目及结果 |
| `POST /{id}/cancel` | 取消整个打包任务 |
| `POST /{id}/retry` | 新建按原快照重试的任务，body 含新的 clientRequestId |
| `POST /{id}/download-link` | 校验产物后返回短期下载链接、文件名和链接过期时间 |

预检载荷：

```json
{
  "dramaId": "2032095628944588801",
  "selection": {
    "include": [
      {"type": "EPISODE", "id": "2032095628944588802"},
      {"type": "SHOT_GROUP", "id": "2032095628944588803"}
    ],
    "excludeShotIds": ["2032095628944588804"]
  },
  "missingVideoPolicy": "SKIP"
}
```

`include.type` 支持 ALL / EPISODE / SCENE / SHOT_GROUP / SHOT；ALL 不传 id。也支持显式 `shotIds`，与 selection 互斥。创建请求提交预检返回的固定 `shotIds`、`expectedPreviewHash`、选项及 `clientRequestId`，不能在创建时重新展开一个已发生变化的父范围。

`previewHash` 覆盖分镜 ID、当前绑定 URL / Take、层级路径 / 名称 / 排序及导出选项，不能用前端计算结果替代。预检不承诺文件已实际下载成功，源可读性和真实大小仍需消费者执行时验证。

## 9. 数据与代码边界

新增 `shot_video_export_task`、`shot_video_export_item` 两张业务表，以及单行调度状态 / 执行令牌记录。

| 对象 | 核心字段 |
| --- | --- |
| task | id、drama_id、name、client_request_id、request_hash、preview_hash、options_json、status、revision、cancel_requested、总数 / 成功 / 失败 / 跳过计数、进度、产物 bucket/key、size、checksum、expires_at、错误、创建 / 开始 / 完成时间、retry_of_task_id |
| item | id、task_id、execution_order、shot_id、episode_id、scene_id、shot_group_id、各层名称与顺序快照、current_video_take_id、take_no、video_url_snapshot、source_bucket/key/version/etag、zip_entry_path、size、checksum、status、error_code、error_message |
| dispatch | 固定主键、当前 task_id、attempt_token、更新时间；只在短事务中领取、释放或恢复 |

唯一约束：task.client_request_id、item(task_id, shot_id)、item(task_id, zip_entry_path)；查询索引覆盖 drama_id / 创建时间及 status / 排队顺序。

后端建议组件：`ShotVideoExportController`、`ShotVideoExportService`、`ShotVideoExportWorker`、`ShotVideoExportArchiveService`、`VideoAssetSourceResolver`。复用现有业务实体、Mapper、MinIO 与任务中心，不将新功能写进渲染批次 Service。

层级遍历和范围展开可从 `VideoBatchPreparation` 提取通用 `DramaShotSelectionService`，并为渲染队列保留原有测试；不能直接复用带提供商 / 模型校验、缺失视频判断相反的 render preview。

前端建议组件：`ShotVideoExportModal.vue`、`ShotVideoExportDrawer.vue`、`api/shot-video-export.ts`；扩展任务中心的 sourceType、详情恢复动作与下载入口，所有实体 ID 保持 string，禁止 Number / parseInt 转换。

数据库迁移需同步独立增量 SQL、`src/main/resources/sql/init.sql`、`docker/mysql/init/01_init.sql` 及 Docker db-upgrade 登记，确保已有环境与新部署一致。首版不添加新的 Maven 依赖。

## 10. 验收

1. 可选整个短剧、多个分集 / 场景 / 镜头组及单镜；层级交叠只导出一次，未归组镜头不遗漏。
2. ZIP 每镜一个当前视频，按工作台顺序组织，中文可正常解压，不同分镜重复源地址仍保留各自文件。
3. 预检后更换 Take 返回 409；创建后更换 Take、重排、改名仍导出原快照，渲染中已有旧视频可正常导出。
4. 缺失项、源对象删除、大小超限和下载中断均有明确结果；部分成功包可正常解压且不含半个视频。
5. 大视频通过固定缓冲区和 ZIP64 完成导出；没有整包内存缓存，超过容量及时终止并清理。
6. 关闭弹窗 / 页面重连不丢任务；进度靠 WebSocket，无定时 HTTP 查询、数据库扫描或 Gateway 任务查询。
7. 连续提交幂等，多实例最多一个打包任务，取消后没有可下载半成品，进程中断可按原快照恢复。
8. 成功下载原始字节，文件校验一致；过期链接可重新签发，过期产物清晰提示，不自动重新导出。
9. 路径非法字符、名称裁剪冲突、CSV 公式、超长路径和异常媒体地址有回归覆盖；未授权短剧 / 任务遵循项目权限边界。

建议落地顺序：先做选择与快照预检，再做后台 ZIP 与下载，最后接入任务中心和恢复 / 取消。首版交付完整闭环，再考虑按集分别打包或生成剪辑软件工程。
