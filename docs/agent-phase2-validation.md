## 真实调用中修复的问题

- 拆解仍在 PENDING 时不读取尚未生成的预览；事务提交后才启动异步任务。
- DeepSeek 多轮调用保留原始空和非空 `reasoning_content`；避免 SDK `extraBody` 产生重复 `messages`，严格 JSON 测试验证实际 HTTP 请求。
- 大工具结果超过预算时，允许减少近期完整轮次并摘要，保留工具调用/结果配对及最新推理字段。
- 提示词请求传入现有导演服务要求的当前镜头输入快照；生成结果使用规划版本和指纹保护。
- 默认造型缺少描述时必须通过 AI 补齐本项目原资产，再刷新指纹与规划。服务端不从剧情关键词猜测设定。
- 新项目道具匹配限定公共库，已有项目限定本项目与公共库；入库再次校验道具归属。旧无效关联可通过合法新规划修复，不因读取指纹而锁死，也不允许继续引用越界资产。
- 提示词服务返回的导演版本已经持久化，应用时直接比对该版本，不再次加一；真正的手工变更仍会阻止过时结果覆盖。
- 大批详细规划出现工具参数截断后增加小批次指引，建议每批 1–4 项文字资产、1–3 镜规划。缺图交付的宠物气泡读取保存的报告，显示补图数量与 ATTENTION 状态，素材齐全则显示准备完成。
